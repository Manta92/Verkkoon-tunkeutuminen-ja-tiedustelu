#### b) rtl_433. Asenna rtl_433 automaattista analyysia varten. Kokeile, että voit ajaa sitä

Aloitin ajamalla `sudo apt install rtl-433`-komennon. Se ei kuitenkaan sellaisenaan toiminut ja ehdotti korjaamaan riippuvuudet(dependencies) komennolla `apt --fix-broken install`.  

    $ sudo apt install rtl-433    
    [sudo] password for kali: 
    You might want to run 'apt --fix-broken install' to correct these.
    Unsatisfied dependencies:
     nmap : Depends: nmap-common (= 7.991+dfsg-1kali1) but 7.99+dfsg-1kali1 is to be installed
     rtl-433 : Depends: libsoapysdr0.8 (>= 0.8.1) but it is not going to be installed
    Error: Unmet dependencies. Try 'apt --fix-broken install' with no packages (or specify a solution)

Kokeilin tätä mutta vastaus oli seuraava error-viesti. Minulla ei ole käyttöoikeuksia tiedostoihin.

    $ apt --fix-broken install    
    Error: Could not open lock file /var/lib/dpkg/lock-frontend - open (13: Permission denied)
    Error: Unable to acquire the dpkg frontend lock (/var/lib/dpkg/lock-frontend), are you root?
    
Kokeilin samaa sudo-käyttäjänä ja sain ilmoituksen että riippuvuuksien korjaaminen epäonnistui. 

    $ sudo apt --fix-broken install
    Correcting dependencies... failed.
    Unsatisfied dependencies:
    Error: Unable to correct dependencies

Seuraavaksi päivitin kaikki mitä päivitettävissä oli `sudo apt update` ja `sudo apt upgrade`- komennoilla ja asensin nmap-kirjaston `sudo apt install nmap nmap-common libsoapysdr0.8`-komennnolla. Päivitykset veivät n. 15 minuuttia. Tämän jälkeen onnistui ajaa komento  `sudo apt install rtl-433`. Ohjelma asentui kansioon /usr/bin.

    $ rtl_433                                                                                                                                                      
    rtl_433 version 25.12 (2025-12-12) inputs file rtl_tcp RTL-SDR SoapySDR
    [SDR] No supported devices found.

#### e) Ultimate. Asenna URH, the Ultimate Radio Hacker.

Seurasin tehtävsivun ohjeita asentaakseni URHn ja se tallentui hakemistoon `/home/kali/.local/bin/urh
`. `pipx ensurepath`-komento sanoi kaiken olevan kunnossa. Kuitenkin rrittäessäni käynnistää sovellusta tuli seuraava ilmoitus: 

    └─$ urh                     
    zsh: illegal hardware instruction  urh

Kysyin Clauden Sonnet 5.5. mallilta apua ja se ehdotti, että tarkistaa arkkitehtuurien yhteensopivuuden seuraavilla komennoilla:

    └─$ uname -m                                              
    python3 -c "import platform; print(platform.machine())"
    pipx environment | grep -i home
    x86_64
    x86_64

Arkkitehtuuri on yhteensopivaa, mutta ongelma pysyy. Yritin myös netistä hakemalla selvittää mistä ongelma voisi johtua. [Hatchjs.com](https://hatchjs.com/zsh-illegal-hardware-instruction/) artikkelissa kerrottiin, että ongelma voi johtua useasta syystä kuten että ydin tai tiedostojärjestelmä ei tue komentoa tai komento ei ole kelvollinen. 

Kokeilin myös vaihtaa komentotulkin bash:iin, mutta URHn avaaminen ei toiminut silläkään. Seuraavaksi kokeilin poistaa kaikki URH:n sovellukseen liittyvän ja yrittää asentaa sen alusta asti uudestaan. 

En osaa sanoa missä meni vikaan, `pipx`:n kanssa on ongelma johon ei meninannut löytyä ratkaisua. Pipx oli asennettu mutta väitti että `pipx`-komentoja ei löydy ja pyysi asentamaan sen uudelleen. Vastasin useaan kertaan kyllä, ja vastaus oli että kyseinen sovellus on jo ajan tasalla. 

    └─$ pipx ensurepath
    Command 'pipx' not found, but can be installed with:
    sudo apt install pipx
    Do you want to install it? (N/y)

En saanut selville mistä tämä johtui, mutta kokeilin vielä asentaa `pipx`n uudelleen komennolla `sudo apt install --reinstall pipx`.
